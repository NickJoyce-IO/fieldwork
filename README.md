# Fieldwork

Free, open-source, hands-on Projects for experienced developers picking up Kotlin, or moving from JavaScript to TypeScript on modern Node.

Each Project is a real-world thing you build in your own GitHub repository, split into Steps of about fifteen minutes each. A Step is a small set of failing tests: you make them pass, push a branch, open a pull request against your own repository, let GitHub Actions check it, and merge. There is no website and no account to create. GitHub is the only record of your progress.

## How to start

1. Pick a Track below, and install its prerequisites.
2. Pick a Project. Each one says what it assumes you already know, so you can start wherever fits rather than at the beginning.
3. Click its **Use this template** link to create your own repository from it, clone that, and follow its README. You won't need to come back here.

Tracks are independent: take either, in any order.

## Kotlin Track

Kotlin, progressing into Spring Boot. Steps run as Gradle tasks, so the Kotlin toolchain is all you need.

Before you start, install:

- JDK 21. Each Project ships the Gradle wrapper, so there is no Gradle to install.
- Git, and a GitHub account.
- The GitHub CLI (https://cli.github.com), logged in with `gh auth login`.

## TypeScript-on-Node Track

TypeScript and modern Node together, for developers coming from JavaScript. Steps are checked by the type-checker as well as the tests, and the tests use Node's built-in test runner.

Before you start, install:

- Node 24 LTS, with the npm that comes with it. Each Project pins both, and `.nvmrc` names the Node version.
- Git, and a GitHub account.
- The GitHub CLI (https://cli.github.com), logged in with `gh auth login`. Projects use it to check that `main` is protected, to protect it for you (`npm run setup`) and to bring in updates (`npm run update`).

## Contributing

Projects are written in this repository and published to their template repositories from it. See `CONTRIBUTING.md` to get started, and `docs/authoring-guide.md` to add or change a Project.

The Track and Project listings above are generated from each Track's `track.json` and each Project's `fieldwork.json`. After changing either, run `npm run fieldwork -- readme` and commit the result. CI fails if the README has drifted from them.
